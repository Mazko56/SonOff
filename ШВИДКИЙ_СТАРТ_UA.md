# Sonoff S60 Lab — як зібрати APK і перевірити розетку

**Це вихідний проєкт Android, не готовий APK.** У поточному середовищі немає Android SDK/Gradle і фізичної Sonoff S60TPF, тому реальну APK-компіляцію та перевірку на розетці провести тут неможливо. Замість цього підготовано проєкт, тести, симулятор і готовий workflow для віддаленої збірки APK.

## Збірка APK через GitHub (без ручного встановлення Gradle)

1. Створіть **приватний** репозиторій GitHub.
2. Завантажте в нього **вміст папки SonoffS60Lab** (включно з прихованою `.github`).
3. На GitHub відкрийте **Actions → Build Android debug APK → Run workflow**.
4. Коли workflow успішно завершиться, скачайте артефакт **SonoffS60Lab-debug-apk** та розпакуйте його — всередині буде інсталяційний `app-debug.apk`.

Альтернатива: відкрити папку в Android Studio з SDK API 35 і натиснути **Build → Build APK(s)**. Жодна з цих компіляцій ще не виконана в цьому середовищі.

## Що реально працює в коді

- Android вмикає локальний вебсервер `127.0.0.1:18765` (панель керування).
- Автоматично шукає через NSD + mDNS `_ewelink._tcp`.
- Є обробка випадку, коли S60TPF не надсилає A-запис IPv4 у mDNS.
- Для **S60TPF Wi-Fi** надсилає команди `POST /zeroconf/switches` і читає `/zeroconf/getState` напряму в пристрій на порту 8081, із AES-128-CBC.
- Виводить ON/OFF, напругу, струм, потужність, споживання за добу/місяць (якщо їх повертає розетка), журнал помилок та дозволяє поділитися ним.
- Вбудований симулятор працює незалежно від розетки; файл **SonoffS60Lab_Browser_Simulator.html** показує його окремо у браузері.

## Перед першим реальним тестом знадобиться

1. **Точна модель на корпусі**: S60TPF (не `S60TPF-M` з Matter і не `S60ZBTPF` із Zigbee).
2. **Номер версії прошивки** в eWeLink.
3. Телефон Android + розетка в тій самій локальній мережі без блокування multicast.
4. **devicekey** — окремий секрет саме цієї розетки, потрібний для зашифрованого локального протоколу. Отримувати його треба авторизованим способом зі свого eWeLink, а не надсилати в чат або вставляти в публічний репозиторій.
5. Бажано мати низькопотужну лампу для фізичної перевірки реле.

Зауваження: точна модель не передається в стандартному mDNS гарантовано, тому перед першою командою передбачена кнопка підтвердження **«Це S60TPF»**, щоб випадково не перемкнути інший Sonoff.

## Якщо не працює

1. `DEVICE.FOUND` є, але немає даних — перевірте авторизований `devicekey`, перегляньте `MDNS.DECRYPT.*`.
2. Не знаходить — перевірте одну Wi-Fi мережу, відсутність AP isolation, multicast UDP 5353, перегляньте `NSD.*` та `MDNS.*`.
3. Є показники, немає керування — шукайте `LAN.REQUEST.FAIL`, `LAN.REPLY.ERROR`, перевірте доступність TCP 8081 і точну модель.
4. Керує, але не оновлює дані — перевірте `LAN.REPLY.STATE`, окремий випадок mDNS TXT без A-запису й оновлення з заводської програми.
5. У застосунку натисніть «Поділитися логами»; перед відправленням зітріть приватні IP/ID, якщо потрібно. Секретний ключ у лог не потрапляє.

## Принципове обмеження

На заводській прошивці **розетка є LAN HTTP-сервером на порту 8081, а Android підключається до неї**. Телефон може мати власний локальний вебсервер для інтерфейсу, але немає підтвердження, що заводська S60TPF підключатиметься до довільного сервера телефона сама. Для цієї дослівної вимоги повний результат поки не досягнуто.

Додаткові посилання, перевірені під час дослідження, описано у `docs/RESEARCH.md`.
