# Sonoff S60 / інші eWeLink: розширена локальна діагностика

## Головне

- **Інтерфейс HTML не змінено.** Діагностика працює автоматично після виявлення кожного пристрою; журнал доступний через чинну кнопку «Допомога» → «Поділитися журналом».
- Відсутній запит до eWeLink API, облікового запису або хмари.
- Немає скидання розетки, зміни Wi-Fi, прошивки чи автоматичного перемикання реле.
- Застосунок **не вміє сам отримувати секретний `devicekey`** із Device ID або mDNS. Без нього на типових зашифрованих Sonoff можливі пошук, TCP/HTTP-діагностика та, лише якщо прошивка дозволяє, відкритий read-only стан. Керування не обійде авторизацію.

## Автоматичні резервні механізми

1. Android NSD `_ewelink._tcp` → Device ID, TXT, сервіс, IP, порт.
2. Власний mDNS-парсер → TXT+SRV+A, запасне отримання IPv4 із UDP-відправника за відсутності A-record.
3. Для відкритого TXT-стану — отримання показників із mDNS. Для зашифрованого TXT — розшифрування тільки якщо власний ключ уже в Android Keystore.
4. Для зашифрованого пристрою **без ключа** — одноразова обмежена TCP-перевірка порту, потім **тільки читальні** `POST /zeroconf/getState`, резервно `POST /zeroconf/info`, за локальною приватною IPv4-адресою. У запиті немає ключів або команд реле. Успішний HTTP/TCP не означає авторизацію. Якщо тіло є відкритим JSON із полями показників, показники можна бачити; на штатній S60TPF це **не підтверджено**.
5. За наявності раніше збереженого ключа — зашифрований LAN `getState` + декодування mDNS. Після підтвердженого стану можливе реле; команди `switches` для S60 і `switch` для сумісних старіших `enhanced_plug` вибираються за реально отриманими полями.
6. Якщо **сам телефон вже приєднаний** до legacy Sonoff AP 10.10.7.0/24, збережено обережну перевірку `/device` (для S60TPF не підтверджено). На домашньому Wi-Fi 192.168.x.x вона не працює.

Усі TCP/HTTP-запити виконуються через **Wi-Fi Android Network**, а не через мобільні дані, навіть коли стільниковий інтернет став основним транспортом.

## Що буде у журналі

- Виявлені Device ID, локальна IP:порт, mDNS-сервіс, SRV-хост, джерело IP та fallback; тип (`plug`, `enhanced_plug`, `th_plug`, `strip` тощо), ознака шифрування, оголошені TXT-поля та **безпечні** значення (`apivers`, `txtvers`, `seq`, `model`, `name`, `uiid`, `fwVersion`, якщо їх справді оголосив пристрій).
- Назву з eWeLink типу «Кімната 2» локально отримати **не можна, якщо пристрій її не оголошує**; модель/UIID не вгадуються за типом.
- IP телефона/префікс Wi-Fi, факт мережевого маршруту, TCP latency/помилки, HTTP-коди, JSON-імена полів, `error`, факт зашифрованості тіла, результат перевірки read-only, наявність ключа в Keystore без його значення, результат авторизації й час оновлення даних.
- Ключі, `iv`, зашифровані пакети, токени, паролі Wi-Fi, SSID і невідомі значення TXT **не експортуються**.

### За наданими логами замовника

`10013bec50` → `192.168.0.171:8081`, тип `enhanced_plug`. Якщо скриншот eWeLink із версією **3.6.4** стосується саме нього, це **не характерний профіль S60TPF** (`UIID 190`, тип `plug`, у SonoffLAN наведено FW 1.2.0); є різні можливі старіші моделі. Поки не отримано справжній productModel або UIID, **називати цю розетку S60TPF не можна**.

## Як перевірити

1. Зібрати APK в GitHub Actions із цього архіву й **оновити**, а не видаляти попередній додаток. Той самий ключ підпису потрібен для збереження Android Keystore.
2. Телефон і пристрої в одній Wi-Fi; увімкнене «Керування LAN» у налаштуваннях розетки.
3. Відкрити APK, дочекатися сканування і діагностики; за 8 пристроїв це може тривати деякий час, бо запити послідовні і з короткими тайм-аутами.
4. «Допомога» → «Поділитися журналом». Надіслати **весь** журнал і «Перевірка з'єднання»; секрети не записуються, але локальні IP та Device ID є.
5. Не скидати розетку кнопкою і не відключати навантаження для тесту без потреби.

### Симулятор

Стандартний симулятор **імітує штатну відмову** в незашифрованому доступі. На Windows:

```bat
cd /d C:\sonoff
py -m pip install cryptography
py tests\fake_s60.py --host 0.0.0.0 --port 8081 --advertise --advertise-ip 192.168.0.102 --devicekey lab-test-key-only
```

Тільки для перевірки логіки «показники без ключа, але керування закрите» запустити із `--public-readonly` в кінці. **Це лабораторна поведінка, вона не доводить, що фізична S60TPF надає показники без ключа.** Підставити актуальний IP ПК, якщо він змінився.

## Що перевірено та що ні

Перевірено локальними тестами: Python симулятор, криптографічний протокол, відмову без ключа, лабораторну відкриту телеметрію, наявність захисту реле, компіляцію основних Java-файлів із тестовими Android-заглушками. **Повна збірка APK на Android SDK і робота з фізичним Sonoff у цій перевірці не виконувались.**
