# Перевірка можливостей автоматичного підключення — 19 листопада 2026

## Твердження, які підтверджують першоджерела

1. **SONOFF S60TPF**: офіційна інструкція описує початкове додавання через eWeLink, Bluetooth/QR і домашній Wi-Fi. Не документує відкритого повного локального commissioning без виробника.
   - https://support.sonoff.tech/s60tpf-usermanual/
2. **SonoffLAN** працює зі штатною прошивкою через LAN, але зашифровані пристрої потребують devicekey. У звичайному сценарії SonoffLAN завантажує ключі з eWeLink і надалі може керувати локально. Назва служби `_ewelink._tcp` не означає, що ключ є у відкритому TXT-записі.
   - https://github.com/AlexxIT/SonoffLAN
   - https://github.com/AlexxIT/SonoffLAN/blob/master/DEVICES.md (S60TPF, UIID 190, `plug`)
   - https://github.com/AlexxIT/SonoffLAN/blob/master/custom_components/sonoff/core/ewelink/local.py
3. **Старий DIY Mode 2.0** і адреса `10.10.7.1` документувалися для BASICR3, RFR3, MINI, D1 — це НЕ доказ можливості такого режиму у S60TPF. Відповідно, запит `/device` у коді є лише пробою для потенційно сумісного AP, а не підтвердженим способом підключення S60TPF.
   - https://sonoff.tech/blogs/news/no-tasmota-and-ewelink-cloud-to-control-the-sonoff-device-yes
4. **S60TPF-M** — інша, новіша Matter-модель. Її вебконсоль доступна через AP 192.168.33.1, і вона має незалежні локальні інтерфейси. APK для S60TPF не реалізує Matter-комісіонування.
   - https://support.sonoff.tech/s60tpf-m-usermanual/
   - https://www.sonoff.in/openedge
5. **OAuth eWeLink** дійсно може повертати devicekey в списку пристроїв, але вимагає зареєстрований APPID та доступ до китайських серверів, тому не відповідає вимозі користувача про повну відмову від хмари.
   - https://github.com/CoolKit-Technologies/eWeLink-API/blob/main/en/OAuth2.0.md
6. **S60TPF LAN може мати аномалії mDNS** і на деяких мережах локальний доступ недоступний, хоча eWeLink працює. Саме тому потрібні логування та польові випробування.
   - https://github.com/AlexxIT/SonoffLAN/issues/1871
   - https://github.com/AlexxIT/SonoffLAN/issues/1772

## Результат для нашого Android-застосунку

- У звичайному домашньому Wi-Fi — автоматичний пошук, немає звернень до `10.10.7.1`.
- При наявному законно отриманому `devicekey` — наявний LAN-клієнт пробує підключення та показники (потрібна фізична перевірка).
- Якщо телефон сам опинився в точці доступу з IPv4 `10.10.7.x/24` — фоновий, тільки читальний GET `http://10.10.7.1/device`; відмова цього ендпоінта не впливає на інші пристрої.
- У поточній заводській S60TPF перше підключення без vendor cloud і без ключа **не підтверджено**. Застосунок не має права підробляти успіх керування.
- Не реалізована зміна Wi-Fi-конфігурації розетки та підключення самої розетки **до** вебсервера телефона. Вбудований сервер телефона слухає лише loopback і показує локальну панель користувачеві.
