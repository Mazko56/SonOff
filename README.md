# Sonoff S60 — Android LAN release candidate

**Реліз:** 1.0.0-rc1 (18.11.2026)  
**Стан:** вихідний код Android. Збирання на цьому середовищі недоступне; попередній проєкт збирається через GitHub Actions. На фізичній розетці S60TPF **ще не тестувався**. **Не можна гарантувати 100% сумісність** без самого пристрою, версії його прошивки й авторизованого `devicekey`.

## Що відрізняється від попередньої версії

- Повністю вилучені симулятор і кнопки тестового режиму з Android UI та з Android API.
- Головний екран орієнтований на користувача: пошук, виявлені розетки, стан, фактична телеметрія та керування.
- Діагностика з логами й системним «Поділитися» винесена в розділ **Допомога**.
- Автоматичний NSD + mDNS IPv4 discovery, у т. ч. обхід відсутнього `A`-запису в деяких S60TPF. IP не вводиться користувачем.
- AES-128-CBC PKCS7 (JCA PKCS5Padding) шифрування локального eWeLink LAN протоколу. Індивідуальний ключ зберігається через Android Keystore.
- Увімкнути/вимкнути, читати дані, показувати фактичні напругу/струм/потужність/лічильники енергії/RSSI (якщо ці поля надає розетка).
- Додаткові функції LED та «Після відновлення живлення» доступні лише тоді, коли розетка повідомила про відповідну підтримку.
- Одна HTTP-команда за раз для уникнення конфліктів з однопотоковим сервером Sonoff; одноразовий повтор при IOException; перевірка підтвердження стану після ON/OFF, без фальшивого позитивного результату.
- Кнопка «Шукати» повторно надсилає mDNS-запит (раніше не робила нічого після першого запуску).
- GitHub Actions: оновлено setup-android@v4, setup-java@v5, вимкнено випадкову появу зеленого статусу без APK.

## Обов'язкові технічні обмеження

1. Ціль: **S60TPF Wi-Fi, UIID 190**, зі штатною прошивкою eWeLink. Не Zigbee S60ZBTPF і не Matter S60TPF-M.
2. **Без IP вручну** — так. Але **без початкової авторизації** — ні: шифрований LAN-контроль потребує індивідуального `devicekey`. Автоматичне отримання цього ключа можливе тільки через відповідну авторизовану eWeLink інтеграцію / developer credentials; їх не було надано. У цьому проєкті ключ вводиться один раз, зберігається захищено на телефоні. Не розміщуйте його в GitHub і не надсилайте розробнику.
3. Вимога «сама розетка під'єднується до сервера телефона» **не доведена й не реалізована**: у штатному eWeLink LAN розетка слухає TCP 8081, а Android її виявляє й відправляє запити напряму. У Android є локальний HTTP-сервер для панелі керування на 127.0.0.1:18765. Ця схема не змінює маршрути eWeLink або прошивку. Змусити штатну розетку встановлювати нові з'єднання із сервером телефона, можливо, взагалі не підтримується заводською прошивкою.
4. Wi-Fi телефон і S60 мають бути в одній мережі, з дозволеними multicast/mDNS; мережі з AP isolation можуть блокувати пошук.
5. Для Android 17 із майбутнім targetSdk 37+ знадобиться адаптація до `ACCESS_LOCAL_NETWORK` або системного засобу вибору пристрою; наразі targetSdk=35.
6. Фоновий сервіс для багатогодинного безперервного контролю не реалізований. Сканер працює, поки відкрито Activity.

## Збірка через GitHub Actions

1. Замініть файли у GitHub-репозиторії вмістом цього ZIP (важливо: папки `app` та `.github` мають бути в **корені** репозиторію).
2. Зробіть commit та push у `main`.
3. Actions → **Build Android debug APK** → успішний запуск → **Artifacts** → `SonoffS60Lab-debug-apk`.
4. Усередині буде `app-debug.apk`. Після встановлення Android може вимагати дозвіл «Встановлювати невідомі застосунки».

> Увага. Це debug APK, а не підписаний production-реліз для Google Play. Перед реальним комерційним використанням потрібні перевірки на фізичній S60TPF та security review.

## Сценарій фізичного тестування

1. Знайти точне маркування **S60TPF** на корпусі й прошивку в eWeLink; телефон у тій же Wi-Fi-мережі.
2. Увімкнути розетку і впевнитися, що eWeLink нормально працює.
3. Відкрити Android-застосунок, почекати на виявлення, натиснути «Шукати» за потреби.
4. Підтвердити маркування S60TPF. Якщо ключ потрібен, власник один раз вводить **власний** devicekey локально.
5. Спочатку перевірити, чи надходять достовірні показники напруги, струму, потужності. Вимкнення/увімкнення перевіряти із безпечним малопотужним навантаженням.
6. Порівняти фізичний стан, індикатор, показники в Android і eWeLink. Перевірити, що застосунок не змінив штатну роботу eWeLink.
7. Якщо не знайшло / не отримує стан / не перемикає — Допомога → Поділитися журналом. Ключі / паролі в ньому не записуються (але можуть бути IP та device ID).

## Які перевірки зроблено

- `python -m unittest discover -s tests -p 'test_*.py' -v` → PASS, 3 лабораторні тести шифрування, HTTP і mDNS.
- `javac ... MdnsPacket.java tests/MdnsPacketSelfTest.java` + `java MdnsPacketSelfTest` → PASS, parsing TXT/SRV без A.
- `node --check` скрипту HTML → PASS.
- Android Manifest XML і GitHub Actions YAML → синтаксичні перевірки PASS.
- **Актуальний Android APK після цих змін:** ще НЕ зібрано; користувач має запустити GitHub Actions.
- **Реальна розетка:** НЕ протестована.
